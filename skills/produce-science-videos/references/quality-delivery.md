# 验收与交付

将结论和证据分开填写 `assets/acceptance.template.md`。不同检查回答不同问题：

| 检查 | 能证明什么 | 不能代替什么 |
|---|---|---|
| 来源逐条核验 | 陈述与证据/许可对应 | 整体叙事和观感 |
| ffprobe、完整解码、哈希 | 文件结构、可读性、完整性 | 真实视听 |
| 数据包一致 | 指定流压缩负载未改变 | 同步和混音听感 |
| ASR 风险检查 | 可能漏读、误读、时序风险 | 原文权威、逐词准确或听审 |
| 联系表与选帧 | 已抽到画面的构图/连续性 | 未抽到的短镜头、连续播放 |
| 完整实际视听 | 实际覆盖范围的内容和感受 | 用户最终批准 |
| 用户确认 | 明确版本与范围的批准 | 未展示版本或新改动的批准 |

## 技术检查

核对尺寸/画幅、帧率、音频采样率/声道、预期时长与文件体积；完整解码查错误。关注开头、尾部、剪切点、补录接缝、片尾声音和字幕停止点。有分轨时检查旁白/音乐各自和合成后版本。

`scripts/media_audit.py` 默认只读结构；`--decode` 完整解码；`--compare-video` 或 `--compare-audio` 检查两个文件对应首个流的压缩包哈希序列。重新编码后哈希不同是正常的，不等于听感必然不同。结果明确写出它没有进行主观视听。

## 内容与体验

先审完整成片，而不是只给很多“通过”的样段。核对因果故事、史料/重建边界、关键实验条件、类比限制、人物身份、科学文字和日期。动作看开始/中间/结果，字幕看原生输出和实际裁切，音乐实际听可懂度与衔接。

### 分层视觉与节奏验收

1. **整片概览**：从最终编码文件按镜头取帧并带时间码排成联系表；检查景别、场景、素材类型、色调与信息密度是否有目的地变化，识别连续重复构图。缩略图条应能帮助辨认问题、行动、证据、结果的阶段；仅纹样、旋转角或粒子数量变化不自动构成新信息。同一对象的持续观察若有科学必要，可以保留长段，不设强制场景数量。不要用帧数代替观看覆盖。
2. **风险加密**：每个关键动作取起点、中段、最大位移/接触点、结果和结束；所有短插镜都应被覆盖。切点前后各取相邻帧，检查黑帧、跳尺度、字幕和动作接缝。固定间隔抽帧可能完全漏过短镜头。
3. **空间复核**：对照镜头空间约定，核对可见表面、透视、遮挡、颗粒/手/物体接触、投影与背景锚点。方形板仰视等高风险机位必须先通过几何自洽检查。
4. **连续播放**：完整观看最终导出，并对快速动作/复杂接缝局部回放，检验速度、抖动、意外放大、停帧和音乐/动作对应。静帧合格不能证明运动合格；解码正常不能证明画面一直在动。预期静止段与异常冻结分开判断。
5. **记录与回归**：每个问题写版本、精确时间码、看到的现象、修复和重检范围。修复后重审受影响镜头及相邻接缝；音轨/时长改动时重新核对后续节点，不把旧报告套到新文件。

联系表文件名、抽帧时间点、连续观看范围、听审范围分别记入验收记录；仅查源码、源图或抽帧，不能标成“完整连续视听通过”。

若当前工具无法实际听或连续播放，交付能提供的机器报告与视觉证据，并明确剩余检查。不要因为检查项数量很多就宣称已经“全面听审”。

## 交付与补丁

仅向当前授权目的地交付。附成片、字幕、来源/权利与署名、必要工程/恢复资料、版本/大小/哈希、已检和未检项。避免把私人声音参考或无再分发权素材混进公开包。

上传后核对目标文件身份、版本、大小并实际下载校验；压缩包在隔离路径校验和恢复。失败或超时先检查可能已上传的副本，再按同一授权范围重试。重试不自动授权扩大权限、换公开渠道或永久删除重复项。

局部修补要注明覆盖哪个版本、替换哪些文件、最终恢复顺序。必要时提供“基础包 + 增量包”的明确组合。用户先看先审时可以分批交付，但不要把“供审阅”写成“用户已通过”。
